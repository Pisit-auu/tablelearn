# กลุ่มวิชา "เลือก 1 จากกลุ่ม" ในตัวช่วยจัดแผน — Design

วันที่: 2026-11-11 · สถานะ: รอผู้ใช้อนุมัติ

## ทำไมต้องทำ

นักศึกษามักมีวิชาที่ "ต้องลง 1 ตัวจากหลายตัว" เช่น หมวดวิชาเลือกเสรี หรือวิชาภาษาที่เลือกได้หลายรหัส ตอนนี้ตัวช่วยจัดแผนรู้จักแค่ "ใช้วิชานี้" ทีละวิชา ถ้าติ๊กวิชาเลือกทั้ง 4 ตัว แผนจะพยายามใส่ทั้ง 4 ตัว ผู้ใช้ต้องลองสร้างแผนทีละตัวเองว่าตัวไหนเวลาลงตัว

เป้าหมาย: ผู้ใช้จับวิชาหลายตัวเป็น "กลุ่ม" แล้วตัวช่วยจัดแผนเลือกมาใส่แค่ 1 ตัวที่เวลาลงตัวที่สุดให้เอง

## สิ่งที่ผู้ใช้ตัดสินใจแล้ว

- กลุ่ม = แผนใส่วิชาจากกลุ่ม **แค่ 1 ตัว** ที่เวลาลงตัว
- ถ้า **ไม่มีวิชาไหนในกลุ่มลงได้เลย → ข้ามกลุ่มนั้น** แล้วจัดวิชาที่เหลือตามปกติ (ไม่ใช่ล้มทั้งแผน)
- **ตั้งชื่อกลุ่มได้** และ **ลบกลุ่มได้**
- **เลือก section เข้ากลุ่มได้**: วิชาในกลุ่มจะใช้ทุก section หรือจำกัดเฉพาะบาง section ก็ได้ (เพิ่มตอนอนุมัติ)
- ใช้งานง่าย — ผู้ใช้ให้ Claude ออกแบบ และรับรองภาพร่าง `.superpowers/brainstorm/124314-1794378058/content/course-groups.html` กับข้อเสนอต่อไปนี้ ("ถูกต้อง"):
  - ทุกอย่างอยู่ในกล่อง "วิชาในตัวช่วยจัดแผน" เดิม ไม่เพิ่มหน้า/หน้าต่างใหม่
  - ปุ่ม "＋ สร้างกลุ่ม" ท้ายรายการ → กล่องเส้นประ ชื่อเริ่มต้น "กลุ่ม N" กดที่ชื่อแก้ได้ทันที มีป้าย "เลือก 1 วิชา"
  - "ลบกลุ่ม" → วิชาในกลุ่มกลับเป็นรายการปกติ ไม่หายจากตัวช่วย
  - ทุกแถววิชามีปุ่ม "ย้ายเข้ากลุ่ม ▾" (รายการกลุ่มที่มี + "+ กลุ่มใหม่…") วิชาในกลุ่มมีปุ่ม "นำออก" — กดเลือก ไม่ใช้ลากวาง (ใช้บนมือถือได้)
  - ติ๊กที่หัวกลุ่ม = ใช้กลุ่มนี้สร้างแผน **กลุ่มนับเป็น 1 ช่องจากสูงสุด 7**
  - ถ้ามีอย่างน้อยหนึ่งวิธีลงวิชาในกลุ่มได้ แผนต้องมีวิชาจากกลุ่มเสมอ ไม่ข้ามทั้งที่ยังลงได้
  - วิชาหนึ่งอยู่ได้แค่กลุ่มเดียว
  - แผนแนะนำแต่ละแผนมีป้าย "<ชื่อกลุ่ม> → <ชื่อวิชา> S.<section>" ถ้าข้ามกลุ่มมีป้ายสีส้ม "ข้ามกลุ่ม <ชื่อ>: ทุกวิชาชนเวลา"

## พฤติกรรมโดยละเอียด

### ข้อมูล
- กลุ่ม = `{ id, name, codes: string[], selected: boolean }` (รูปแบบจริงให้ผู้สร้างตัดสิน)
- วิชาในกลุ่มยังเป็นวิชาใน `plannerPool` เหมือนเดิม กลุ่มแค่อ้างถึงรหัสวิชา
- **section ของวิชาในกลุ่มใช้กลไก "ดู section / เลือก section" เดิม** (`plannerSectionPicks`) — ถ้าไม่ได้เลือก section = ใช้ทุก section; ถ้าเลือกไว้ = ใช้เฉพาะที่เลือก แถววิชาในกลุ่มต้องมีปุ่ม "ดู section" แบบเดียวกับแถวปกติ (Claude's call: ใช้ของเดิมแทนการสร้างระบบเลือก section ใหม่)
- เก็บกลุ่มใน localStorage พร้อมข้อมูลตัวช่วยจัดแผนเดิม อ่านแล้วข้อมูลผิดรูปต้องไม่ทำหน้าพัง (ทิ้งกลุ่มที่เสีย, ตัดรหัสที่ไม่อยู่ใน pool ออก)
- เอาวิชาออกจากตัวช่วย (หรือ "ล้างทั้งหมด") → รหัสนั้นหลุดจากกลุ่มด้วย กลุ่มที่ว่างแล้วยังอยู่จนกว่าผู้ใช้ลบ (Claude's call)

### การติ๊กและนับ
- วิชาในกลุ่ม **ไม่มีช่องติ๊กของตัวเอง** ติ๊กได้ที่หัวกลุ่มเท่านั้น (Claude's call: กันสับสนว่า "ติ๊กวิชาในกลุ่ม" แปลว่าอะไร)
- ย้ายวิชาที่ติ๊กอยู่เข้ากลุ่ม → ช่องติ๊กของวิชานั้นหายไป; ถ้ากลุ่มยังไม่ถูกติ๊ก ให้ติ๊กหัวกลุ่มให้อัตโนมัติ (Claude's call: ผู้ใช้ตั้งใจใช้วิชานั้นอยู่แล้ว)
- ตัวนับ "ใช้สร้างแผน X/7" นับวิชาเดี่ยวที่ติ๊ก + กลุ่มที่ติ๊ก (กลุ่มละ 1); กลุ่มที่ว่างไม่นับและติ๊กไม่ได้
- ลบกลุ่มหรือนำวิชาออกจากกลุ่ม → วิชากลับเป็นรายการปกติ **ไม่ติ๊ก** (Claude's call: กันเกิน 7 โดยไม่รู้ตัว)

### การสร้างแผน
- วิชาเดี่ยวทำงานเหมือนเดิมทุกอย่าง (ล็อก, section picks, เงื่อนไขเวลา, คะแนน)
- กลุ่มที่ติ๊ก = ช่องหนึ่งในการค้นหา ตัวเลือกของช่องนั้นคือทุก section ที่อนุญาตของทุกวิชาในกลุ่ม แผนผลลัพธ์มีวิชาจากกลุ่ม 1 ตัว (1 section)
- **ข้ามกลุ่มเฉพาะเมื่อไม่มีตัวเลือกใดในกลุ่มลงได้กับแผนนั้น** — ถ้าค้นแล้วมีแผนที่ใส่วิชาจากกลุ่มได้ ห้ามคืนแผนที่ข้ามกลุ่มนั้น
- ถ้าวิชาในกลุ่มถูกล็อกอยู่ในตารางแล้ว ถือว่ากลุ่มนั้น "ได้แล้ว" ด้วยวิชาที่ล็อก ไม่ต้องเลือกเพิ่ม (Claude's call: ล็อก = ต้องได้ section นี้)
- แผนที่ข้ามกลุ่มควรได้คะแนนต่ำกว่าแผนที่ครบ (ผู้สร้างกำหนดน้ำหนัก) และเหตุผลต้องบอกว่าข้ามกลุ่มไหน
- ป้ายในแผนแนะนำตามที่ระบุในหัวข้อผู้ใช้ตัดสินใจ
- ต้องไม่ทำให้การสร้างแผนช้าลงจนรู้สึกได้: ปัจจุบันตัดตัวเลือกต่อวิชาไว้ 12 section และหยุดที่ 20 แผน — กลุ่มต้องมีเพดานตัวเลือกแบบเดียวกัน (ผู้สร้างกำหนดตัวเลข)

### ข้อตัดสินใจของ Claude หลังอ่านทวน (ผู้ใช้ยังไม่ได้ยืนยันทีละข้อ)

- **หลายกลุ่มแย่งเวลากัน** (กลุ่ม A กับ B ลงได้ทีละกลุ่ม แต่ลงพร้อมกันไม่ได้): แผนที่คืนต้อง **ครอบคลุมจำนวนกลุ่มมากที่สุดเท่าที่ทำได้** ถ้ามากสุดได้แค่ 1 กลุ่ม ให้คืนทั้งแผนที่ได้ A และแผนที่ได้ B (คนละแผน) แต่ละแผนมีป้ายสีส้มบอกว่าข้ามกลุ่มไหน — ไม่คืน 0 แผน กติกา "ห้ามข้ามทั้งที่ลงได้" จึงหมายถึง: ห้ามคืนแผนที่ครอบคลุมกลุ่มน้อยกว่าที่ทำได้
- **"ลงได้" นับจากตัวเลือกทั้งหมดของกลุ่ม** ไม่ใช่แค่ที่ค้นภายใต้เพดาน: ก่อนค้น ให้กรองตัวเลือกของกลุ่มทิ้งเฉพาะ section ที่ชนกับวิชาที่คงไว้/ล็อก (เช็กเร็ว ไม่ติดเพดาน) แล้วค่อยตัดเพดานจากตัวเลือกที่เหลือ ป้ายข้ามกลุ่มใช้คำว่า "ข้ามกลุ่ม <ชื่อ>: ไม่มีวิชาที่ลงเวลาได้กับแผนนี้" (ไม่อ้างว่า "ทุกวิชาชนเวลา")
- **วิชาในกลุ่มที่อยู่ในตารางแล้ว**: ถ้ากลุ่มถูกติ๊ก วิชาในกลุ่มที่อยู่ในตาราง (ไม่ล็อก) ถือเหมือนวิชาเดี่ยวที่ติ๊ก คือ **ถูกแทนที่ได้** ด้วยตัวเลือกจากกลุ่ม; ถ้ากลุ่มไม่ถูกติ๊ก วิชาเหล่านั้นคงไว้เหมือนวันนี้ ถ้าวิชาในกลุ่มถูกล็อกไว้ 2 ตัวขึ้นไป ให้เคารพการล็อก (แผนมีทั้งสอง) และถือว่ากลุ่มได้แล้ว — ผู้ใช้ล็อกเองโดยตั้งใจ ไม่ถือเป็นข้อผิดพลาด
- **section picks ของวิชาในกลุ่ม**: "กลุ่มถูกติ๊ก" มีผลเหมือน "วิชาถูกติ๊ก" ต่อวิชาสมาชิก — เลือก section ในกลุ่มแล้วติ๊กหัวกลุ่มให้อัตโนมัติ; เอาติ๊กหัวกลุ่มออก = ล้าง picks ของสมาชิก (เหมือนเอาติ๊กวิชาออกวันนี้); ย้ายวิชาที่ติ๊กและมี picks เข้ากลุ่ม = picks ติดไปด้วย; นำวิชาออกจากกลุ่ม = กลับมาไม่ติ๊กและไม่มี picks (สอดคล้องกับพฤติกรรมเดิม)
- แถววิชาในกลุ่มมีปุ่ม "ดู section" และ "เอาออก" (ออกจากตัวช่วย) เหมือนแถวปกติ เพิ่มจากปุ่ม "นำออก" (ออกจากกลุ่ม)

### บทพาทำ / ปุ่ม ?
- ข้อความปุ่ม ? ของ "ตัวช่วยจัดแผน" เพิ่มประโยค: "วิชาที่ลงตัวไหนก็ได้ จับรวมเป็นกลุ่ม ระบบจะเลือกให้ 1 ตัวที่เวลาลงตัว" (Claude's call)
- ไม่เพิ่มภารกิจใหม่ และบทพาทำเดิมต้องยังผ่านได้ (ขั้น "ติ๊กวิชาแล้วกดสร้างแผน" ยังใช้กับวิชาเดี่ยวได้)

## เป้าหมาย / ไม่ใช่เป้าหมาย / สิ่งที่ถือว่าล้มเหลว

เป้าหมาย: สร้างกลุ่ม ใส่ 3–4 วิชา ติ๊ก กดสร้างแผน แล้วได้แผนที่มีวิชาจากกลุ่มตัวเดียวพร้อมป้ายบอก ภายในไม่กี่คลิก ทั้งบนคอมและมือถือ

ไม่ใช่เป้าหมาย: กลุ่ม "เลือก N ตัว" (N > 1); กลุ่มซ้อนกลุ่ม; ลากวาง; แชร์กลุ่มผ่านห้องร่วมกัน (ห้องแชร์แค่ตาราง ตัวช่วยจัดแผนเป็นของเครื่องใครเครื่องมัน เหมือนเดิม)

ถือว่าล้มเหลวแม้จะทำงานได้:
- แผนมีวิชาจากกลุ่มเดียวกันมากกว่า 1 ตัว
- แผนข้ามกลุ่มทั้งที่มีวิชาในกลุ่มลงได้
- ลบกลุ่มแล้ววิชาหายจากตัวช่วย
- ข้อมูลกลุ่มเสียแล้วหน้าเว็บพัง
- ฟีเจอร์เดิมของตัวช่วยจัดแผน (ล็อก, เลือก section, เงื่อนไขเวลา, บทพาทำ) ทำงานต่างจากเดิมเมื่อไม่ได้ใช้กลุ่ม

## ข้อจำกัด

- Next.js 16 / React 19, `app/page.tsx` client component เดียว, CSS ใน `app/globals.css` ใช้ token ตาม DESIGN.md, ข้อความไทยทั้งหมด
- ตรรกะการสร้างแผนอยู่ใน `generateSchedulePlans` ใน `app/page.tsx` — แนะนำแยกส่วนคำนวณที่เกี่ยวกับกลุ่มเป็นฟังก์ชันบริสุทธิ์ในไฟล์ใหม่ เพื่อเขียนเทสต์ด้วย `npm test` (node:test) เหมือน `app/onboarding/*`
- ไม่เพิ่ม dependency

## ปล่อยให้ผู้สร้างตัดสินใจ
